# Niti — приватный продуктовый roadmap

Обновлено: 20 июля 2026

## Фокус

Главная продуктовая гипотеза: Niti должен максимально сокращать путь от найденной
вакансии до управляемого процесса поиска работы. Ближайшая цель — позволить новому
пользователю войти без лишнего трения и сохранить первую вакансию за несколько минут.

Основная метрика активации:

- доля зарегистрированных пользователей, сохранивших первую вакансию в течение 10 минут.

Вспомогательные метрики:

- конверсия регистрации в завершённый onboarding;
- доля регистраций через Google;
- доля успешно разобранных ссылок;
- доля импортов, в которых правильно определены должность и компания;
- среднее количество исправленных пользователем полей перед сохранением;
- доля сохранённых вакансий, которые позднее стали откликами;
- недельный возврат активированных пользователей.

## Порядок реализации

### Этап 0. События и базовые метрики

Цель: измерять эффект следующих изменений, не создавая сложную аналитическую систему.

- [ ] Зафиксировать события: регистрация, вход, завершение onboarding, начало импорта,
      успешный/неуспешный разбор, сохранение вакансии, создание отклика.
- [ ] Не отправлять в аналитику описание вакансии, резюме и другие чувствительные данные.
- [ ] Добавить простой способ считать основную метрику активации.

Готово, когда: можно сравнить путь пользователя до и после запуска Google Auth и импорта.

### Этап 1. Регистрация и Google Auth

Цель: быстрый и понятный вход без обязательного создания пароля.

- [ ] Добавить `Continue with Google` на страницы регистрации и входа.
- [ ] Оставить email/password как альтернативный способ входа.
- [ ] Добавить отдельную модель внешних идентичностей пользователя
      (`provider`, `provider_subject`, `user_id`) для безопасного связывания аккаунтов.
- [ ] Продумать связывание Google с существующим аккаунтом и исключить дубликаты email.
- [ ] Перенести авторизацию из `localStorage` в безопасную cookie-сессию с обновлением.
- [ ] Добавить выход со всех устройств/отзыв активных сессий.
- [ ] Добавить восстановление пароля для email/password.
- [ ] Сделать ошибки входа и отмены OAuth понятными пользователю.
- [ ] Решить, нужен ли обязательный выбор Job Seeker / Recruiter / Mix. Если главный
      сценарий — поиск работы, рассмотреть Job Seeker по умолчанию с изменением в Settings.

Готово, когда: новый пользователь входит через Google, не создаётся второй аккаунт для
существующего email, сессия безопасно переживает перезагрузку страницы, выход её отзывает.

### Этап 2. Импорт вакансии по ссылке

Цель: превратить ссылку в редактируемую карточку вакансии без записи в БД до подтверждения.

Пользовательский сценарий:

1. Пользователь вставляет ссылку на Dashboard или странице вакансий.
2. Niti загружает и разбирает страницу.
3. Пользователь видит редактируемое превью заполненных полей.
4. Пользователь выбирает `Save for later`, `I already applied` или `Cancel`.
5. Перед сохранением Niti проверяет дубликаты.

MVP-поля:

- должность;
- компания;
- локация;
- зарплата;
- формат работы;
- тип занятости;
- описание;
- URL и платформа-источник.

Backend:

- [ ] Добавить `POST /vacancies/import/preview`, не выполняющий запись в БД.
- [ ] Сначала извлекать `JobPosting` из JSON-LD.
- [ ] Использовать Open Graph и HTML-разметку как следующий слой.
- [ ] Добавить адаптеры только для площадок, которые реально нужны первым пользователям.
- [ ] Использовать AI-разбор очищенного текста только как fallback.
- [ ] Возвращать найденные поля, предупреждения и способ извлечения.
- [ ] Нормализовать URL и удалять известные tracking-параметры.
- [ ] До сохранения запускать существующую проверку дублей.
- [ ] Добавить SSRF-защиту: только HTTP(S), запрет private/loopback/link-local адресов,
      повторная проверка после DNS и редиректов, лимиты времени, размера и числа редиректов.
- [ ] Не передавать cookies пользователя на внешние сайты.
- [ ] Обработать сайты с авторизацией, CAPTCHA и антибот-защитой понятным fallback-сценарием.

Frontend:

- [ ] Добавить заметное поле `Paste job link` на Dashboard и странице вакансий.
- [ ] Показать состояния загрузки, ошибки и частично заполненный результат.
- [ ] Переиспользовать существующую форму вакансии для редактирования превью.
- [ ] Реализовать `Save for later` как создание вакансии без отклика.
- [ ] Реализовать `I already applied` как атомарное создание вакансии и application
      со статусом `applied`.
- [ ] При найденном дубле предложить открыть существующую запись или обновить её источник.

Метрики качества импортера:

- успешным считается импорт, где определены как минимум должность и компания;
- отдельно считать техническую ошибку загрузки и неполный разбор доступной страницы;
- сохранять только техническую диагностику, не полный HTML страницы.

Готово, когда: поддерживаемые публичные ссылки дают редактируемое превью, ничего не
сохраняется без подтверждения, а сценарий `I already applied` завершается одним действием.

### Этап 3. Быстрое управление воронкой

Цель: сделать Niti удобным не только для добавления, но и для ежедневного ведения поиска.

- [ ] Добавить Kanban по статусам applications.
- [ ] Реализовать быстрое изменение статуса без открытия полной формы.
- [ ] Сохранять историю смены статусов для будущей аналитики.
- [ ] Добавить быстрые действия из карточки: интервью, задача, заметка, отказ, оффер.
- [ ] Проверить мобильный сценарий управления воронкой.

Готово, когда: пользователь обновляет статус отклика за одно действие и видит всю активную
воронку на одном экране.

### Этап 4. Follow-up и напоминания

Цель: возвращать пользователя в продукт в момент, когда требуется действие.

- [ ] Предлагать follow-up через настраиваемое число дней после отклика или контакта.
- [ ] Связать напоминания с существующими tasks, applications и contacts.
- [ ] Добавить блок `Needs attention` на Dashboard.
- [ ] Позволить отложить, завершить или отключить рекомендацию.
- [ ] Не отправлять email/push без явного согласия пользователя.

Готово, когда: просроченные и рекомендуемые действия видны в одном месте и не создают
дублирующиеся задачи.

### Этап 5. Быстрое сохранение из браузера

Цель: сохранять вакансию, не копируя ссылку вручную.

- [ ] Сначала стабилизировать публичный контракт импорта.
- [ ] Проверить простой bookmarklet как дешёвый эксперимент.
- [ ] После подтверждения спроса сделать browser extension с `Save to Niti`.
- [ ] Использовать тот же preview и подтверждение, что и в web-приложении.

Готово, когда: вакансия с открытой страницы попадает в стандартный preview Niti одним
действием, без отдельной логики парсинга в расширении.

### Этап 6. CV matching и внешние интеграции

Цель: добавлять автоматизацию только после стабилизации основного цикла.

- [ ] Сравнивать требования вакансии с выбранной версией CV.
- [ ] Показывать ключевые совпадения, пробелы и подтверждение каждого вывода текстом вакансии.
- [ ] Не менять CV автоматически без явного подтверждения пользователя.
- [ ] Исследовать импорт интервью из календаря.
- [ ] Исследовать связывание ответов рекрутеров из email с applications и contacts.
- [ ] Добавить экспорт данных и удаление аккаунта до масштабирования интеграций.

## Принципы и границы

- Сначала уменьшаем трение в основном сценарии, затем добавляем AI и интеграции.
- Любой автоматически извлечённый результат остаётся редактируемым.
- Preview никогда не означает согласие на сохранение.
- Парсер не должен превращаться в универсальный crawler в первой версии.
- Новые поля добавляются в доменную модель только после подтверждённой пользовательской нужды.
- Личные данные, резюме и описания вакансий не используются для обучения или аналитики
  без отдельного явного согласия.

## Ближайшие решения

- [ ] Подтвердить основную аудиторию: Job Seeker или равноправные Job Seeker / Recruiter.
- [ ] Выбрать первые 3–5 сайтов для проверяемого MVP импортера.
- [ ] Решить, какой минимум собственной аналитики нужен до первой публичной проверки.
- [ ] После этого разбить Этап 1 на технические задачи и реализовывать его без расширения scope.
