# Niti — приватный продуктовый roadmap

Обновлено: 25 июля 2026 (отмечен прогресс реализации этапов 0–3)

## Фокус

Главная продуктовая гипотеза: Niti должен максимально сокращать путь от найденной
вакансии до управляемого процесса поиска работы. Ближайшая цель — позволить новому
пользователю войти без лишнего трения и сохранить первую вакансию за несколько минут.

Основная метрика активации:

- доля зарегистрированных пользователей, сохранивших первую вакансию в течение 10 минут.

Вспомогательные метрики:

- конверсия регистрации в завершённый onboarding;
- доля регистраций через Google;
- доля успешно разобранных ссылок;
- доля импортов, в которых правильно определены должность и компания;
- среднее количество исправленных пользователем полей перед сохранением;
- доля сохранённых вакансий, которые позднее стали откликами;
- недельный возврат активированных пользователей.

## Порядок реализации

### Этап 2. Импорт вакансии по ссылке

Цель: превратить ссылку в редактируемую карточку вакансии без записи в БД до подтверждения.

Пользовательский сценарий:

1. Пользователь вставляет ссылку на Dashboard или странице вакансий.
2. Niti загружает и разбирает страницу.
3. Пользователь видит редактируемое превью заполненных полей.
4. Пользователь выбирает `Save for later`, `I already applied` или `Cancel`.
5. Перед сохранением Niti проверяет дубликаты.

MVP-поля:

- должность;
- компания;
- локация;
- зарплата;
- формат работы;
- тип занятости;
- описание;
- URL и платформа-источник.

Backend:

- [x] Добавить `POST /vacancies/import/preview`, не выполняющий запись в БД.
- [x] Сначала извлекать `JobPosting` из JSON-LD.
- [x] Использовать Open Graph и HTML-разметку как следующий слой.
- [x] Добавить адаптеры только для площадок, которые реально нужны первым пользователям
      (8 адаптеров под выбранные площадки).
- [ ] Использовать AI-разбор очищенного текста только как fallback — отложено осознанно:
      частичный разбор + редактируемая форма закрывают сценарий; в pipeline оставлен seam.
- [x] Возвращать найденные поля, предупреждения и способ извлечения.
- [x] Нормализовать URL и удалять известные tracking-параметры.
- [x] До сохранения запускать существующую проверку дублей.
- [x] Добавить SSRF-защиту: только HTTP(S), запрет private/loopback/link-local адресов,
      повторная проверка после DNS и редиректов, лимиты времени, размера и числа редиректов.
- [x] Не передавать cookies пользователя на внешние сайты (и не пересылать cookies между
      редиректами).
- [x] Обработать сайты с авторизацией, CAPTCHA и антибот-защитой понятным fallback-сценарием.

Frontend:

- [x] Добавить заметное поле `Paste job link` на Dashboard и странице вакансий.
- [x] Показать состояния загрузки, ошибки и частично заполненный результат.
- [x] Переиспользовать существующую форму вакансии для редактирования превью.
- [x] Реализовать `Save for later` как создание вакансии без отклика.
- [x] Реализовать `I already applied` как атомарное создание вакансии и application
      со статусом `applied`.
- [x] При найденном дубле предложить открыть существующую запись или обновить её источник.

Метрики качества импортера:

- успешным считается импорт, где определены как минимум должность и компания;
- отдельно считать техническую ошибку загрузки и неполный разбор доступной страницы;
- сохранять только техническую диагностику, не полный HTML страницы.

Готово, когда: поддерживаемые публичные ссылки дают редактируемое превью, ничего не
сохраняется без подтверждения, а сценарий `I already applied` завершается одним действием.

Готово, когда: пользователь обновляет статус отклика за одно действие и видит всю активную
воронку на одном экране.

### Этап 5. Быстрое сохранение из браузера

Цель: сохранять вакансию, не копируя ссылку вручную.

- [x] Сначала стабилизировать публичный контракт импорта (preview/commit реализованы;

Готово, когда: вакансия с открытой страницы попадает в стандартный preview Niti одним

### Этап 6. CV matching и внешние интеграции

Цель: добавлять автоматизацию только после стабилизации основного цикла.

- [ ] Сравнивать требования вакансии с выбранной версией CV.
- [ ] Показывать ключевые совпадения, пробелы и подтверждение каждого вывода текстом вакансии.
- [ ] Не менять CV автоматически без явного подтверждения пользователя.
- [ ] Исследовать импорт интервью из календаря.
- [ ] Исследовать связывание ответов рекрутеров из email с applications и contacts.
- [ ] Добавить экспорт данных и удаление аккаунта до масштабирования интеграций.

## Принципы и границы

- Сначала уменьшаем трение в основном сценарии, затем добавляем AI и интеграции.
- Любой автоматически извлечённый результат остаётся редактируемым.
- Preview никогда не означает согласие на сохранение.
- Парсер не должен превращаться в универсальный crawler в первой версии.
- Новые поля добавляются в доменную модель только после подтверждённой пользовательской нужды.
- Личные данные, резюме и описания вакансий не используются для обучения или аналитики
  без отдельного явного согласия.
